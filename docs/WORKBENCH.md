这是 2026-11-09 的初步可用版本。新建任务已接入 7 项检测工具、Skills 与 RAG，详见 [知识增强检测](KNOWLEDGE_DETECTION.md)。入口为 `vulnmind ui`，只监听 `127.0.0.1`。生产部署、多人账户和独立质量验收仍暂缓。

## 启动与使用

在项目目录运行：

```powershell
.venv/Scripts/python.exe -m vulnmind ui --port 8765
```

也可以运行项目根目录 `start-workbench.cmd`（前台）或 `start-workbench-background.cmd`（后台常驻）。打开 `http://127.0.0.1:8765/`，保留服务进程运行；在终端按 Ctrl+C 关闭。当前用户的 `.env` 已配置数据库、证据/报告目录、本机审批与报告签名，三个 HTTP 能力 `fetch`、`crawl`、`validate-run` 已启用。不要把 `.env` 复制进文档或版本库。

新环境需先安装 `pyproject.toml` 中的依赖、配置 PostgreSQL/pgvector 与可信 WSL `VulnMindLab`，备份数据库后迁移至 `0019_durable_step_failed`。已有开发环境可用 `scripts/setup_durable_runtime.py` 先备份再升级。该脚本仅接受 loopback PostgreSQL，并核对知识片段数量保持不变。

1. 点击“本地演示靶场”，工作台在自有 WSL 内启动临时 HTTP 服务，自动填写源码、部署、范围和演示认证。默认使用规则模式，不调用付费模型。
2. 点击“创建并开始分析”，任务和源码摘要持久保存。也可自行填写有授权的仓库与部署，明确 IP 网段、部署版本和授权依据。
3. 在“源码与接口”查看函数、静态路由与部署的关联。没有静态匹配的导入端点会明确标注。
4. 每轮在“请求与审批”查看具体方法、URL、参数和正文；批准后才发送。拒绝后本任务停止主动验证。
5. “证据与复核”显示基线、各次对照、状态码、响应摘要、证据 ID、规划理由和独立复核意见。
6. 完成后点击“校验证据链”或“下载报告”。下载前重新核对回执、报告、证据归属、响应哈希及已配置签名。

新建任务默认两轮、总预算 18 次请求；最多三轮、60 次。每项检查 3 次或 6 次对照请求，每轮最多两项。内置演示默认三轮、30 次。配置中的轮数是上限，规划器或复核器可以提前结束；报告如实记录实际请求数量。

## v1 已交付的 1–4 项（v2 增量见上方链接）

| 原未完成项 | 当前可用实现 | 本版边界 |
|---|---|---|
| 仓库与 Web 统一关联 | 一个持久任务绑定源码摘要、部署版本、静态路由、具体 HTTP 请求、证据与报告；仓库流程作为可恢复子流程 | Python 装饰器路由为主；不声称静态路由证明了线上调用链，部署对应由操作者确认 |
| 更深入的自动验证 | 基线与两次不同挑战、状态/截断检查、表达式求值差分、输入反射及数据库错误线索 | 只自动确认具体表达式求值行为；反射不是 XSS，错误提示不是 SQL 注入已证实，不执行任意 RCE |
| 更自主的 Agent 协作 | 规划角色根据源码信号、已有观察和独立复核意见选择剩余子任务；每轮重新规划，允许提前停止；意见与异议保存 | 有界动作目录，不生成任意工具或攻击脚本；不是无限动态任务图或任意多个模型的自由协商 |
| 复杂 Web/API | 同源 Bearer/Cookie，GET、JSON POST、表单 POST，OpenAPI JSON、HAR 与显式映射导入 | 不自动操作浏览器登录、JS 页面、验证码；HAR 仅提取端点及参数名，不复用录制凭据/正文值 |

模型模式使用当前 DeepSeek 配置，调用两个独立角色；规则模式明确标识，未调用模型。模型只看到候选路由、参数名、静态信号和结构化观察元数据，不接收源码正文、HTTP 响应正文或认证值。模型输出必须通过 schema 和动作 ID 白名单校验，不能越过审批扩大目标范围。

## 接口输入

自动提取 Python `@app.get`、`@app.post`、`@app.route`、`@router.api_route` 等字面量装饰器。扫描不导入或执行仓库文件，最多索引 200 个 Python 文件、单文件 1 MB、总读取 8 MB、200 个路由。摘要针对已索引文件，不代表整个大型或多语言仓库的 Git commit。文件发生变化需新建版本任务。框架路由前缀、动态拼装和复杂参数模型需通过显式映射补充。

显式 JSON 示例：

```json
[
  {"method":"GET","path":"/search","parameters":["q"]},
  {"method":"POST","path":"/api/render","parameters":["name"],"encoding":"json"},
  {"method":"POST","path":"/form","parameters":["q"],"encoding":"form"}
]
```

包含 `{id}`、`<id>` 的模板路径不直接执行。请导入授权范围内的具体路径；此时只标注人工端点映射，除非与静态路由精确匹配。OpenAPI `$ref`、嵌套 JSON、文件上传和 GraphQL 专项策略尚未展开。当前验证器为参数生成独立的标记值，不能自动满足所有业务必填条件；4xx/认证失败会显示证据不足。

HAR 仅保留同源 GET/POST 的路径和参数名；Cookie、Authorization、请求正文值不持久化到任务。认证值单独存入 Windows 当前用户 DPAPI 加密文件，任务只保存配置 ID。它只发送到绑定 Origin，不跟随重定向。当前凭据不提供跨用户迁移或自动刷新。

## 恢复、校验与存储

任务、阶段和 HTTP 回执存于 PostgreSQL。源码与部署绑定、规划、审批、每个请求、证据、复核、报告均有持久阶段。完成回执与业务写入、成功审计一起提交。服务重新启动后，中断任务显示为“已中断”，不会自动补发未知请求。

在“阶段与恢复”同时查看主流程与仓库子流程。结果未知的 `running` 阶段需要明确重试理由，并确认可能重复执行；也可以终止。按钮只允许处理当前任务及其固定子流程。仍在运行的任务不能同时恢复。审批过期、源码改变、凭据缺失或授权到期，需要修正条件或新建任务，不会静默扩大权限。

已完成的任务可直接打开查看，不再执行网络；重新运行协调器会验证并重用已有回执。报告下载是只读校验，不依赖目标仍在线。真实响应最多保存 200 KB，界面每段预览 1200 字；认证回显被脱敏。报告保留结构化观察与响应摘要，完整可恢复回执在数据库中，备份时应同时包含数据库和证据/报告目录。

- `.devtools/runtime/workbench/credentials`：当前 Windows 用户的加密凭据。
- `.devtools/runtime/workbench/demo-v2/repository`：自有演示源码。
- 配置的 `report_root`、`evidence_root`：内容寻址报告、签名和证据。
- `evaluation/workbench_v2_model_smoke_20261109.json`：知识增强模型闭环及恢复、无重复重放记录；不带 v2 的文件为历史样例。
- `evaluation/workbench-ui-20261109.jpg`：实际界面截图。

不要同时启动多个工作台服务操作同一开发数据库。模型/HTTP 阶段有工作流锁，但本版没有多用户调度、权限管理或生产服务管理器。服务重启后演示服务端口可能变化，旧任务证据仍可读；继续新演示应使用新的部署配置。真实目标凭据与部署不受演示服务影响。

## 开发验证

```powershell
.venv/Scripts/python.exe -m pytest tests/unit/test_workbench_inputs.py tests/integration/test_workbench.py -q
$env:VULNMIND_RUN_HTTP_LIVE='1'
.venv/Scripts/python.exe scripts/test_local_postgres.py --require-pgvector
.venv/Scripts/python.exe scripts/workbench_smoke.py --model
```

最后一个命令只允许启动内置自有靶场，并对该脚本创建的具体请求计划签名审批；不能传入外部 URL。`--model` 使用已配置模型，产生正常模型调用费用。不加该选项则使用规则模式。它完成报告后再次重放，并断言不重复模型调用和 HTTP 请求。
