# 仓库分析 MVP（候选范围）

> 2026-11-07：新 `workflow-run` 和 HTTP 能力已在 [DURABLE_WORKFLOWS.md](DURABLE_WORKFLOWS.md) 单独说明。本页后续关于未拆分阶段、HTTP 关闭及 0016 的内容保留为旧 `workflow-scan` 的演进记录，不适用于新入口。

本说明固定首个内部试用版本的目标，不代表已发布或通过安全验收。仅分析已有明确授权的本地仓库。运行人员负责限制数据库、授权文件、报告及证据的访问；现有 CLI 不提供用户登录或多租户隔离。

## 包含的能力

在 PostgreSQL 和受控 Windows/WSL 环境下，创建项目、提供有效授权范围、执行仓库扫描、查询结果、记录人工反馈并生成报告。基础分析包含 Python TLS 配置规则；Gitleaks 和 Trivy 为显式启用的 WSL 沙箱选项。可导入外部 Semgrep SARIF 和 Bandit JSON；导入不代表本程序运行了这些扫描器。可选知识检索、模型规划和建议性复核需要额外配置；未启用模型仍可运行基础扫描。

CLI 不提供浏览器界面。报告中的发现默认待验证；扫描未发现问题不意味着仓库安全。模型意见和人工反馈的含义以报告标注为准。

## 最小流程

先人工审阅迁移，并依据 `DEPLOYMENT.md` 配置数据库、报告目录和可选证据目录。以下示例仅展示命令形状；实际授权文件必须反映权利人的真实授权，时间包含时区，目标必须存在且位于授权根内。

```powershell
vulnmind doctor
vulnmind project-create --name "authorized-repository"
vulnmind scan --project-id <project-uuid> --repository <absolute-repository-path> --scope-file <authorization-json>
vulnmind findings --scan-id <scan-uuid>
vulnmind report --scan-id <scan-uuid>
vulnmind verify --scan-id <scan-uuid>
vulnmind finding-feedback --scan-id <scan-uuid> --fingerprint <fingerprint> --verdict needs_more_info
vulnmind report-regenerate --scan-id <scan-uuid>
```

`verify` 的 `incomplete` 并非成功：例如规则未产生可独立核对的证据文件时会出现不完整状态。扫描或项目创建返回 `unknown` 时先检查数据库及审计，不要盲目重试。报告与证据不包含在数据库事务中，需与数据库协调备份。

## 未纳入首版

真实在线 `fetch`、`crawl`、`validate-run` 仍被阻断；`evidence-gc --apply` 停用。离线 Web 快照分析单独存在，但不纳入本版本推荐的仓库流程。LangGraph 检查点还不能保证扫描副作用的安全恢复，扫描中断后不能声称自动恢复或自动重试安全。

Docker 镜像不包含 WSL 沙箱，不能直接提供上述沙箱扫描器；具体部署及验证状态以 `STATUS.md` 最新记录为准。上线前须在目标环境复核授权、WSL 与文件系统隔离、权限、数据保留、密钥、备份恢复、审计及资源限制，并对确定的代码快照执行完整测试；本文件不构成验收。

## 主图恢复实验进度

迁移 `0015_workflow_operations` 增加阶段认领记录；针对同一任务和阶段，只有一个调用者能认领，已完成的记录可读取结果 UUID，仍处于 started 的记录视为结果未知，不自动重试。该记录和外部操作不处于同一事务，不能证明操作是否发生；未知状态需要另行核查，也没有自动恢复或人工调解入口。该表一旦有记录，降级迁移会拒绝删除表。

`workflow-scan` 将授权→规划→整体仓库扫描图接入 CLI，默认运行内置 Python TLS 检查。可显式使用 `--gitleaks-sandbox`、`--trivy-sandbox` 启用 WSL 沙箱扫描器，也可通过 `--semgrep-sarif`、`--bandit-json` 导入外部扫描报告。`--agent-plan` 让 DeepSeek 从已启用的分析器中选择，未选择项写入报告限制。`--agent-review` 启用建议性复核。`--knowledge-context` 在 PostgreSQL 中使用现有混合检索并记录上下文清单；`--agent-knowledge` 需要 `--agent-review`，并将选中的知识发送至模型服务提供建议。模型调用可能产生费用；知识内容和受限发现元数据会根据所选选项外发。此入口不支持真实 HTTP。需要先在目标数据库审阅并应用迁移至 0016，再为每次新任务生成 UUID：

```powershell
vulnmind workflow-scan --workflow-id <new-uuid> --project-id <project-uuid> --repository <absolute-repository-path> --scope-file <authorization-json>
vulnmind workflow-status --workflow-id <same-uuid>
```

相同 UUID 和相同参数重试成功完成的任务时返回原扫描 ID，不再次扫描；参数变化拒绝。结果为 `unknown` 时不会自动重试，状态查询返回 operation ID。此入口将 operation ID 同时用作 scan ID 和根审计 call ID，可通过 `scans`、`report` 和 `audit-trace --call-id <operation-id>` 核查。未知状态并不表示扫描一定完成或失败；不存在扫描行也不足以证明没有执行文件访问。不要为绕过未知状态而更换 UUID 重试。授权过期或不再满足范围时，即使查询已有扫描结果也会拒绝运行；已知 scan ID 的常规只读查询另有各自权限要求。

外部报告的路径和 SHA-256 纳入任务绑定，读取分析时再次校验实际字节；报告在两次读取之间变化时停止该任务并保守返回 unknown。重复提交需提供同路径、同内容的报告。摘要可检测内容变化，不能证明报告来源真实或外部扫描确曾发生。

模型规划为单独的持久阶段：规划结果、完成状态和终态审计在同一数据库事务中提交；扫描前中断且规划已提交时，重新提交相同任务可复用规划，无需重新调用规划模型。读取规划时校验请求摘要、选择内容及完整审计链；审计链有未哈希事件或超限会拒绝继续。若模型调用期间中断，规划状态为 unknown，不自动再次调用模型，也尚无推断结果或重试入口。`workflow-status` 返回规划与扫描各自的 operation ID，可用 `audit-trace` 分别查询。模型复核仍属于扫描整体操作，并非独立可恢复节点；启用复核的重放仍需能初始化模型配置。SQLite 扫描内的部分复核与工具子事件仍可能随业务事务回滚。已完成扫描的重放会重新校验扫描归属、状态和当前报告文件的内容哈希；无法核实时返回 unknown，需人工核查。

迁移 0016 在存在规划记录或规划阶段认领（包括未完成认领）时拒绝降级，以免旧版本忽略认领并再次发出模型请求；必须先通过受控迁移方案处理历史，不能直接删除认领记录。

升级前应停止旧版本工作进程，待正在运行的任务结束后再迁移并启动新版本；新旧版本并发执行同一工作流不受阶段认领协议保护。历史上已开始或完成的扫描不会因缺少新规划记录而触发新的规划调用。

`workflow-status` 只显示数据库记录的阶段状态，并不自行校验审计链、规划内容或报告完整性；状态显示 completed 不能代替上述独立校验。同参重放或 `--reconcile` 遇到已有独立规划记录时会验证该记录；旧版本已开始或完成的扫描可能没有独立规划记录，仍保留兼容读取。

主图在扫描完成或恢复后执行只读报告核验节点，重新检查当前授权、操作与扫描身份、扫描归属及状态，并读取和核对最新报告的内容哈希及报告内的扫描/项目 ID。核验失败返回 unknown；恢复文件后可用同参重试核验，不会重跑已完成的扫描。恢复 unknown 扫描时也检查报告内的扫描/项目 ID，避免误用另一次扫描的有效报告。该节点不另存阶段回执，每次调用都会重新读取；它不等于证据文件、报告签名或漏洞真实性验证，应使用 `verify` 查看对应检查及其 incomplete 状态。

可在 `--knowledge-context` 同时指定 `--staged-knowledge`，使知识上下文清单在扫描提交和报告核验后作为独立阶段生成；不指定时保持原有扫描事务内生成方式。独立阶段从已持久化发现与观察重建候选，再运行本地 Qwen/PG 混合检索；其清单、阶段完成记录和终态审计同一数据库事务提交，清单及请求摘要与审计链绑定。恢复时重新核对扫描归属、清单和审计，已提交的清单不会重复检索。该清单本身不会送给模型；若另选 `--agent-knowledge`，模型知识建议仍在扫描整体阶段执行，并可能再次检索/外发资料。

`vulnmind workflow-context --workflow-id <uuid>` 可在单个数据库读取快照中核对扫描与清单的绑定、清单摘要和完整审计链后，返回历史引用 ID、选择原因和 token 估计；不会返回知识正文。它是历史的不可信参考记录，不能证明当前知识库未改变或漏洞成立。命令依赖数据库访问权限，当前没有独立用户身份认证或租户隔离。

若扫描已提交而知识阶段尚未认领，同参普通调用可继续知识阶段而不重扫；已认领但未能确认提交时保持 unknown，不自动重试。`--reconcile` 不会启动知识检索：如果它恢复了扫描但知识阶段尚未完成，结果仍为 unknown，须在检查后使用同参普通调用继续。知识阶段完成后再次核验报告和授权；扫描与清单位于不同事务，期间知识库可能变化，清单只反映该阶段实际检索时点，不是扫描时的知识库快照。重建超过 1000 条发现或存在不完整观察历史时失败关闭。模型复核、证据和报告生成仍未独立恢复。

规划不会冻结仓库、扫描器二进制、漏洞库或知识库。若规划后才继续扫描，执行时读取的是当时的仓库和工具状态；需要可复现结果时应由部署方提供并保护固定快照。外部导入报告另按前述摘要绑定。

扫描业务提交与操作完成标记是不同事务，所以提交后中断仍可能留下 unknown。若需核查已提交的结果，可用原来完全相同的 workflow-scan 参数附加 `--reconcile`：它不会启动扫描、初始化或调用模型。只有输入绑定与当前授权匹配、扫描行已完成且项目匹配、报告内容哈希有效、完整审计链校验通过、根事务明确提交且没有未完成的子事件时，才将结果登记为 completed，并写入关联审计；任何条件不满足仍返回 unknown。审计链有历史未哈希事件或超过 10000 条时也会拒绝恢复。

此恢复只登记能够验证的已提交结果，不证明发现真实，也不能判断缺失的扫描是否从未执行；没有强制重试接口。报告文件与数据库不能原子提交，文件核验反映读取时点。可选的独立知识上下文阶段如上所述；模型研判、证据和报告生成仍处于整体扫描阶段。此入口不是完整多 Agent 主流程，也没有生产验收。
