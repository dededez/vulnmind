# 检测工具、Skills 与 RAG 接入（2026-11-09）

新建工作台任务默认使用 `pipeline_version=2`。旧任务未设置该字段时继续使用 v1；历史记录不会补写知识引用或重新发送请求。数据库迁移头仍是 `0019_durable_step_failed`，无需修改业务表结构。

## 当前流程

源码快照 → 静态路由 / 导入接口关联 → 可恢复仓库子流程 → 漏洞类型候选 → 每轮 Skills + RAG 快照 → 规划 → 精确请求审批 → 隔离差分检测 → 证据落库 → 使用同一知识快照独立复核 → 下一轮或签名报告。

知识用于选择方法、解释信号和排查误报；目标的漏洞证据仍必须来自实际代码 / HTTP 观察。开启模型模式后，Planner 和 Critic 均收到 `skill:` 和 `rag:` 上下文，输出引用 ID 必须存在于该轮快照。规则模式保存并核对 Skill 的工具适用清单，执行固定检测器，不声称模型已经理解知识文章。

## 实际检测能力

| 工具 ID | 请求数 | 当前判定与边界 |
|---|---:|---|
| `sql_boolean` | 6 | 重复基线、真假条件和反转顺序一致才产生候选；不枚举数据库。当前适配单引号字符串位置，不能覆盖所有 SQL 语法 |
| `sql_error` | 3 | 引号挑战独有 SQL 错误特征；认证拒绝、截断或对照相同不产生有效结论 |
| `xss_context` | 3 | 两个惰性自定义标签进入 HTML 元素上下文，产生 HTML 注入候选；不等于浏览器脚本执行 |
| `template_expression` | 3 | 两组独立算术对照确认具体求值行为；不推断 RCE |
| `reflection` | 3 | 双标记反射线索；不直接判定 XSS |
| `cors` | 3 | GET 接口对两个无关 Origin 反射且允许凭据，产生策略候选；仍需浏览器和敏感数据证明 |
| `security_headers` | 3 | HTML 响应重复缺少 CSP / nosniff，报告加固建议；不是独立漏洞证明 |

静态类型还包括 SSRF、路径遍历、命令执行、反序列化、XXE、开放跳转。这里只识别调用信号，不做跨函数污点分析，也没有对应主动验证器，界面标注“需补充上下文”。复杂动态路由、JavaScript DOM 执行、双账户越权差分、文件上传、完整 SQL 方言、时间盲注及 sqlmap / ZAP / Nuclei 外部扫描器尚未接入。不能把 11 个知识主题称为 11 个已实现的主动验证器。

每轮最多 2 项、总共最多 3 轮；新建任务默认 18 次请求、可设 3–60 次。SQL 布尔检查按 6 次计费，预算不足的动作不发送。源码支持的候选优先，其他候选在工具之间交错排列。报告列出未执行候选数量，结束不代表所有类型都检查完毕。

## Skills 和知识库

`src/vulnmind/workbench/resources/skills/` 提供 11 个版本为 `2.0.0` 的产品 Skill，包含适用条件、步骤、误报、证据、修复与参考来源。它们随 Python 包分发；不会执行目标仓库内的 Skill 或任意命令。每轮记录选中 Skill 的完整内容、工具清单、版本和语义 SHA-256；已完成快照不再读取磁盘。

`resources/corpus.json` 是项目编写的方法摘要，不是 OWASP 原文复制。每卡携带来源、版本、内容摘要和漏洞类型元数据。已向开发数据库追加 11 文档 / 11 片段：原 812 片段与向量保留，总计 **823**。本地 Qwen 向量回填结果为 `new_vectors=11, reused=812`。同一 corpus 再导入结果 `skipped=11`；同标题内容或元数据改变会报冲突，不覆盖旧知识。

混合模式使用已有 PostgreSQL FTS + pgvector 检索，按 RRF 融合，每类型最多 3 条。记录实际 query、片段 ID、排名、原始内容、来源、版本、信任标签、内容摘要与编码器版本。关键词模式是明确选择，不是混合失败后的暗中降级。检索故障进入可恢复错误状态；无匹配显示 `no_matches`。本地向量模型和其缓存缺失时，应安装既有模型依赖或明确选择关键词模式。

11 个 Skill 中，5 个主题对应当前 7 个主动工具，随候选进入规划 / 复核。其余 6 个主题供静态线索调查和后续验证器扩展使用，本版不会凭知识卡自动产生对应探测请求。

## 安装到另一个开发环境

先备份对应数据库，再在项目根目录运行：

```powershell
.venv/Scripts/python.exe scripts/ingest_corpus.py src/vulnmind/workbench/resources/corpus.json --size 2000 --overlap 100
.venv/Scripts/python.exe scripts/backfill_embeddings_optimistic.py --apply --batch-size 8
```

混合检索沿用已有模型指纹校验，不混用不同模型的向量。本机还通过 `SkillIndexer.sync(SkillLoader(ROOT/'skills'))` 登记了 11 个 Skill 元数据；工作台直接加载包内 Skill 并保存快照，不依赖索引表自动更新。

## 界面和恢复

新建表单可选择检测器和检索模式。“类型与知识”显示端点类型映射、未执行候选、每轮 Skill/RAG 快照；“证据与复核”显示模型实际引用。“请求与审批”的摘要同时绑定知识快照。报告完整性检查验证知识快照、引用、证据关联和签名。

每个知识阶段都有 Journal 回执。恢复读取已保存知识，避免知识库或 Skill 更新后改变同一轮判断依据。模型响应不合格式也保留未知阶段，由明确恢复重试；不会为重试模型而重复已完成 HTTP 请求。

实际样例与测试结果见 `evaluation/KNOWLEDGE_DETECTION_DELIVERY_20261109.md`。生产运行和独立质量验收仍按用户要求暂缓。
