# 检索、证据删除和真实 HTTP 后续验收条件

2026-11-08 更新：下方 HTTP 保持关闭、证据删除保持关闭为历史门槛；当前 HTTP broker 已开放，Windows 证据 GC 已增加事务锁和句柄删除。实际范围和边界见 WORKFLOW_CONTINUATION.md。独立检索评测与生产条件仍未验收，本轮用户明确暂缓。

本记录不授予网络扫描或实际删除权限，不代表任何生产验收通过。开发、测试与部署仍需遵循具体目标授权和工作区规则。

## 检索评估

- 现有 18 题为开发冒烟题；`evaluation/knowledge_holdout_20261105.json` 的 12 个正例和 4 个无答案问题由同一开发 Agent 编写，不是独立专家标注。调过参的结果不能再充当独立验收。
- 新评测集应由未参与实现或调参的人员标注文档、片段、关键事实及无答案情况，保留题目版本、来源快照和标注分歧；分别衡量文档与片段命中、无答案拒答、引用支持、延迟和资源占用。
- `scripts/evaluate_sparse_experiment.py` 的 OR 与三词阈值仅是只读实验；后者看过本批样本后选择。无关结果不等于可回答，不能据此直接启用。
- `scripts/compare_chunk_boundaries.py` 只比较英文单词结束边界，未验证语义、开始边界、代码块完整性或检索表现；不应据此重切开发库。
- 语义支持没有自动证明。可核验摘录的文本存在不代表摘录蕴含回答；低置信度、冲突和缺少事实需继续人工评估。

## 模型与向量来源

`scripts/embedding_provenance.py` 离线记录当前缓存文件摘要；这不是签名认证。`scripts/backfill_embeddings_optimistic.py --apply` 逐项校验旧向量后写入模型标识、缓存版本、文件摘要集合的摘要、内容、文档版本和向量摘要；之后对已登记且一致的向量可复用。计算在表锁之外，写入前短事务锁表并复核数据。一次性 PostgreSQL 已测试增量、模型及向量不一致、并发修改和失败不提交。首次登记和实际开发库结果以本轮运行记录为准。

`PostgresDenseRetriever` 对带来源标记的库要求调用者提供预期模型身份，拒绝混用或不匹配；已选片段还会检查文本和向量摘要。`knowledge-ask --retrieval hybrid` 会离线核对本地模型文件，提供该身份。直接使用更底层仓储接口或绕过应用修改数据库仍不在这一检查范围内。

仍有限制：目前未保存向量原始生成时间；纯旧格式数据库在未提供预期身份时仍可作为兼容模式查询。本机缓存摘要不能证明发行方身份，历史向量数值一致也不能证明其最初来源。生产启用前仍需评估更大规模的锁时长、文件哈希成本及故障恢复。

## 证据实际删除

保持关闭。启用前至少应明确平台目录句柄与链接处理、非协作写入者的威胁边界、路径替换与并发引用场景；在隔离的真实文件系统及 PostgreSQL 环境中验证权限、符号链接/重解析点、检查与使用竞争、恢复和审计。dry-run 通过不等于可以安全删除。

## 真实 HTTP

保持关闭。恢复方案须明确授权对象、有效期、范围和审批身份；对解析地址、重定向、代理和 DNS 变化逐跳强制范围与出站策略，约束方法、速率、资源、敏感信息及数据保留。在明确授权的隔离靶场进行正反向端到端验证，再单独审核开放条件。

本地数据库恢复演练和测试数据库不代表生产恢复及容灾已验收。生产环境需实测权限、身份、密钥、备份恢复、容量和故障处理。Git 工作区存在其他修改及删除记录，应逐项确认归属后再整理；不得以批量清理方式消除脏状态。
